# Firefox (AMO) source submission

Firefox for Android: best effort, untested on device (decision 2026-10-20). The manifest sets no `gecko_android` key; the float opens as a tab there (docs/BROWSERS-GUIDE.md B15).

What AMO's reviewer needs to reproduce the build byte-for-byte, per
`extension/tools/build-browsers.mjs firefox` and the AMO source-code
submission requirement (see `research/51d-legal-privacy-licensing.md` §2:
"any transpiled or minified build needs the pre-build source, a README with
exact tool versions and the commands to reproduce an identical copy; build
tools must be open source and locally runnable").

| Tool | Version |

`extension/package.json` declares no `engines` field and the build uses no

scripts will reproduce the same output; the pinned versions above are what
this submission was actually built with, not a hard requirement.

## The one command that rebuilds the unsigned build

Run from `extension/`:

```bash
node tools/build-browsers.mjs firefox
```

(`node tools/build-browsers.mjs all` builds every target, Firefox included,
from the same one source tree — see that file's own header comment, "One
source, eight targets.") The result is:

- `dist/firefox/` — the unpacked, unsigned Firefox build (load via
  `about:debugging` → *This Firefox* → *Load Temporary Add-on* → its
  `manifest.json`, or submit for signing at addons.mozilla.org)
- `dist/qa-wrap-3.7.1-firefox.zip` — the same folder, zipped

Both come from `extension/manifest.json` plus the transform in
`manifestFor()`/`TARGETS.firefox` (`extension/core/capabilities.js`,
`extension/tools/build-browsers.mjs`): permissions Firefox does not
implement are dropped, the background is declared as an event page instead
of a service worker, and `browser_specific_settings.gecko` (id, minimum
version, `data_collection_permissions`) is added. Every other file — every
content script, every UI file, the whole ISTQB model — is copied verbatim
from the source tree by `tools/lib-ship.mjs`'s shipping list; nothing among
them is Firefox-specific.

## No minified or generated code beyond what this command produces

QA Wrap's own source — every file under `background/`, `content/`, `core/`, `platform/`,
`offscreen/`, `popup/`, `options/`, `sidepanel/`, `report/`, `ui/`,
`reporter/`, `annotate/`, `diagram/`, `devtools/`, `replay/`, `api/` — ships
as the plain, unminified JavaScript/HTML/CSS/JSON committed to the
repository. `node tools/build-browsers.mjs firefox` does not compile,
bundle, transpile or minify any of it; it only writes two files that do not
exist in the source tree, and both are produced by that single command, from
data already in the repository:

- `manifest.json` — `JSON.stringify(manifest, null, 2)` of the object built
  in `manifestFor()`, itself `structuredClone(base)` (the repository's own
  `manifest.json`) with the documented Firefox-only edits applied; nothing in
  it is generated content, only a filtered/annotated copy of a tracked file.
- `BROWSER.md` — a short static readme (`readmeFor()`) listing exactly the
  changes just made, for a person loading the package by hand.

The one exception, present identically in every one of the eight browser
builds and not specific to this command, is vendored third-party code:
`vendor/axe.min.js` (axe-core 4.13.0, MPL-2.0), shipped pre-built exactly as
Deque released it, never modified, and named with its version, licence and
upstream source in `vendor/README.md` and `NOTICE` — copied by the shipping
list, not produced by the Firefox build step. `tools/release-check.mjs`
("bundled third-party code — vendor/axe.min.js", "no eval / new Function in
shipped code", "no remotely hosted code loaded") asserts this on every
release, including the one this file was written against.

The document fonts (Thmanyah, base64 in `ui/fonts.css`) are generated by
`tools/build-fonts.mjs` from licensed files that are not in the package;
see `NOTICE`.
